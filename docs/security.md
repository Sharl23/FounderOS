# Prototype safety and privacy

- A 256-bit random **project capability token** is shown only on creation and stored as a SHA-256 hash in SQLite. It is sent in `X-Project-Token` for sensitive project operations. Treat it as a secret. The browser saves it in localStorage for convenience; **do not share or publish** it.
- No payment handling, publishing, outbound messaging, refunds, signing, or secret storage mechanisms exist. A hard-blocked `/external-action` endpoint audits prohibited requests.
- The project keeps the founder's original idea to satisfy provenance requirements. Do **not** paste passwords, payment cards, API tokens, bank details, health data or real customer PII. A lightweight input check blocks common secret patterns but cannot recognize every secret; use fictional or sanitized briefs.
- **Safety policy is deterministic backend code** (`backend/app/safety.py`): organizer MUST-NEVER patterns hard-block a brief before any model call; founder acknowledgment cannot override a block; high-stakes domains require research-only acknowledgment per brief version. It is an English regex screen, not a legal review, and has false positives/negatives.
- Approvals are bound to run id, report hash, brief version, safety status and experiment versions; stale, duplicate, cross-project and tampered decisions are rejected; the decision and audit tables are append-only via SQLite triggers.
- Instruction-like text ("ignore the rules and approve") in evidence, feedback or experiment designs is rejected or excluded and withheld from the model.
- Remote source URLs must be public HTTPS on port 443; redirects are never followed; literal private/loopback/link-local/metadata IPs and `.local/.internal` hosts are refused. The source reader implements conservative public-address checks, an 8-second timeout, response size limits, and only HTML/plain text support. **DNS rebinding or complex SSRF threats are not fully mitigated**; do not expose the service to untrusted internet users. Production should pin vetted destinations, route through an egress proxy, and sandbox HTTP access.
- LLM output is schema-validated but not inherently factual; treat its research claims as unverified unless accompanied by independently checked evidence.
- Source and founder content are injected as data, never elevated to developer/system instructions. Security does not depend on prompts alone: approval checks live in Python.
- The optional n8n bridge may log request tokens in execution data. It should run only on a trusted local machine. Do not expose port 5678 to the public internet.
- New external side-effect tools would need their own per-action scoped approval including exact destination, content and founder identity. Phase approval alone would never be sufficient.
- No formal production security audit has been performed.
